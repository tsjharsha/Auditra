# IBM Bob 2.0 Integration & Usage

## Overview

IBM Bob 2.0 was utilized extensively as the primary development environment and AI coding workflow during the construction of the Auditra verification engine. 

While Auditra's ultimate goal is to verify AI-generated code (acting as the "Zero-Trust Fabric"), the underlying infrastructure, FastAPI routing, cryptographic hashing mechanics, and React frontend components were all scaffolded and developed using the IBM Bob 2.0 AI workflow.

### Development Role vs Runtime Role
It is important to draw a strict boundary between development and runtime:
1. **Development (IBM Bob 2.0):** Used to architect, write, and refactor the Auditra codebase. Bob authored the SSE streaming logic, the React hook structures, and the AST validation engine.
2. **Runtime Verification (Optional LLMs):** During the live demonstration, Auditra acts as an independent verifier. If a judge opts to run the engine in "Live AI Mode" (rather than Deterministic Demo Mode), Auditra calls an external LLM (e.g., LLaMA-3 via Groq) to simulate an AI proposing a patch. This demonstrates Auditra's ability to verify code generated by *any* AI system, including Bob.

Auditra is the natural extension of IBM Bob 2.0—it is the security layer that allows enterprises to confidently deploy the code that Bob writes.
